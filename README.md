# 城堡突袭 · v1.4 dev5.1.1（修订版）

**《副件契约修订 · 标准副件悬浮文本框架 V3.0》**

零依赖、零外部资源的 2.5D 卷轴动作游戏。解压后**双击 `index.html` 即玩**，普通 `<script>` 顺序加载，`file://` 协议下可运行；也可用 `python -m http.server 8000` 等本地服务打开。画面由 WebGL 渲染，配乐与音效由 WebAudio 实时程序化合成，存档走 `localStorage`（键 `castleRaid.save.v1`，<5MB）。dev5 及更早旧档自动升级，**无需清档**。

> **本修订版**按《标准副件悬浮文本框架 V3.0》重做副件悬浮文本、把「原生色宽色阶@实际段长段色」改为已契约时的运行时装配信息，移除面向玩家的代际称谓，并把【名称解释】里的同名 BUFF 顶替规则实装为通用机制；护盾与 BUFF 改为按队伍槽位隔离、后台照常计时。
>
> 上一版（dev5.1）按反馈重做资源节奏与界面归位：**MP 每秒回 1 点**、**PP 不再自然回复**（改由魔法泉水 / 恢复道具 / 100 金币一键补给恢复）、全部技能 **CD 压缩到 1.0~4.0s** 由 PP 兜底；**灵路 · 副件 / 神兵持有 / 一键补给从背包搬进【角色 / 队伍】页**；天赋重置改为消耗洗髓丹随机刷新一项资质、新号初始晶豆 0；移动端区域信息卡加收起按钮与限宽避让；根除夜樱试炼 BOSS 出现在地图入口的旧 bug。

**本地服务提示**：`localhost:8000` 与 `file://` 是不同源，`localStorage` 互不互通，属浏览器正常行为。全部 37 个 JS + 1 个 CSS 均带版本指纹 `?v=1.4dev5.1.1`，升级后按一次 **Ctrl + F5**，或直接双击 `index.html`（推荐）。发布新版本时必须同步修改 `index.html` 里的全部 `?v=` 指纹，避免 304 缓存把旧 JS 留下来（dev1.5 曾因此导致按钮全失效）。

## 二、dev5.1 修复：夜樱 BOSS 又跑到地图前面

**根因（本次挖到底）**：dev1.2 修过一次「相机把玩家往前拖」，但 dev5 又出现两条残留路径——

1. 切图往返 / 复活到入口后，`P.x` 可能停在 170，而 `startTrial()` 仍以「玩家当下位置」为锚生成 BOSS；
2. 更关键：`harbor.init()` 与复活时只把 `st.trial.ref = null`，**没有杀掉旧 BOSS 实体**，它脱离 `bossRef` 后被通用 AI 一路追到入口，于是玩家在对话点看到「BOSS 在地图最前面」。

**修复（五层）**：① BOSS 唯一以对话点 `HARBOR_NPCS.trial.x/depth` 为锚（±120px），不再读 `P.x`；② 玩家吸附到对话点并清速度 / 击退；③ `camLock` 显式解除 + 大 dt 一步对齐相机，避免 lerp 滞后把画面留在入口；④ `updateTrial()` 给 BOSS 加**对话点 ±260 领地约束**，通用 AI 无法带它离场；⑤ `harbor.init()` 与 `main.js` 复活时清理全部残留 `sakuraBoss` 并终止试炼。

QA 覆盖：从大学城切回港口再走**真实 F 对话**开试炼、主循环多帧、玩家被拖回 `x=170` 的极端场景、重新进图清理，BOSS 始终在对话点附近。

## 四、灵路系统（整合规格 0.4，逻辑不变）

### 合法拆解（段长只允许 1 / 3 / 6 / 9，不能 5+4）

| 拆解 | 段 | 定位 |
|---|---|---|
| `9` | 9 | **推荐**：单件满色宽 |
| `6+3` | 6,3 | 双配，高成本 / 极限输出 |
| `3+3+3` | 3,3,3 | 三配，整活 / 高成本 |
| `1×9` | 1×9 | **收藏级**：被 C=1 启动惩罚压住 |

### 公式（全部在 `js/game/soulpath.js`）

```
Q_req   = W · e_R                                  有效色宽需求品质
Q_supply= Σ_seg n_seg · min(e_seg, e_R)           高色装低需求封顶舍弃
E_power = min(1, Q_supply / Q_req)^β
F(k)    = max(0.45, 1 - 0.08(k-1))                跨段碎片惩罚
L(C)    = C≥3 ? 1 : (C/3)^1.5   → L(1)=0.192     单段启动惩罚
G       = 1                          (MP ≥ D_sum)
        = .55 + .45·(MP/D_sum)^1.3  (MP < D_sum)
E_i     = E_power · F(k) · L(C) · G · S_attr
Power_type = T_m · Σ Q_i · Base_i · E_i · M_i      M_rank = 0.9^(rank-1)
```

- **效率 E ∈ [0,1] 只由灵路适配决定；品质 Q 只负责版本强度与推荐度**。
- 属性阈值 `S_attr` 按双攻非线性插值（`r=0.30→0.26 / 0.50→0.52 / 0.77→0.95 / ≥1→1.00`），阈值按本游戏实际属性量级标定（A 120 / S 190 / X 260，暴击档 180 / 285 / 390）。**Lv1 角色无法白嫖高级法器**。
- 关键结论（QA 复现）：赤 9 装碧系 A/S 满效率、装 X 约 89.2%；双 X 约 133.6% 单 X、三 X 约 156.5%；三 S < 单 X、三 A < 单 S；高色装赤系 A 提示浪费 270；`1×9` 收藏级。
- 显化槽 **主 1 + 辅 1**，其余副件只显示灵路环 / 图标，最多 2 个局内实体，不改变数值。

### 通用 BUFF 容器（`buffs.js`）

| 规则 | 实现 |
|---|---|
| 不同名加算 | 同一 `group` 乘区内所有非同名 BUFF 的 `value` 求和；伤害公式 `(1 + P.buff.dmg + god)` 不再连乘 |
| 同名顶替 | `apply()` 先比 `left`，长者优先；`left` 相同（±1e-6）比 `value`，大者优先；常驻视为 `Infinity` |
| 常驻 BUFF | `dur` 为空 → `permanent`，不参与 `tick` 清除，悬浮显示 ∞ |
| 角色隔离 | `key = c0..c3`（队伍槽位），护盾 / 旧式 buff 另由 `team.js` 快照与恢复 |
| 后台计时 | `tick(dt)` 遍历全部槽位；`team.tick` 另递减后台槽位的旧式 `buff.t`；护盾用绝对时间戳自动过期 |

### 切换角色时的状态表

| 状态 | 切走 → 切回 |
|---|---|
| 护盾（普通 / 法术 / 真实） | **保留**（未到期）；不会被队友继承 |
| 临时 BUFF | **后台照常倒计时**；常驻 BUFF 不计时 |
| 8 维战斗等级 | **归零**（dev1.3 既有规则，保持） |
| 异常状态 | **清除**（dev1.3 既有规则，保持；束缚禁止切换） |
| HP / MP / PP | 按角色独立保留 |

### 悬浮说明补全

八维方块显示 `×1.60` 与「速度 -6 级」式说明；BUFF 方块显示效果、剩余时间、常驻标记与顶替规则；护盾方块显示三类数值、剩余秒数与「切换不传递」。
